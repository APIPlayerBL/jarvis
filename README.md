# Jarvis — голосовой ассистент для Windows

Локальный голосовой помощник: wake word «Джарвис» → распознавание речи → интент →
действие на ПК → озвучка. Большинство команд выполняется локально за миллисекунды,
облачная LLM подключается только для сложных или разговорных запросов.

> Основной мозг — **MiMo V2.6 Flash** через агрегатор **AITUNNEL** (без VPN,
> оплата в рублях, 0.56/56 ₽ за 1M токенов). Резерв — DeepSeek V4.1 Flash на
> том же ключе, дальше Mistral/YandexGPT/Groq. Локальная модель отключена и
> выгружена, GPU не используется. Проверка: `python main.py --health` →
> `via: deepseek:mimo-v2.6-flash`.

Что сделано по плану оптимизации:

| Приоритет | Изменение | Эффект | Где |
|---|---|---|---|
| P0 | Динамический набор инструментов | −30…50% токенов, точнее | `brain/brain.py` |
| P0 | Защита от prompt injection | внешний текст = данные | `common/guard.py` |
| P0 | Стриминг LLM → TTS | первый звук ~1 с | `brain/brain.py`, `tts/speaker.py` |
| P1 | Контекст 2–3 реплик | уточнения и «повтори» | `ui/controller.py` |
| P1 | OCR активного окна + кэш | быстрее, приватнее | `eyes/screen.py` |
| P1 | Лёгкий wake word | меньше CPU/RAM в простое | `ears/model_manager.py` |
| P2 | Piper / edge-tts | качество голоса | `tts/speaker.py`, `setup_tts.py` |
| P2 | YandexGPT fallback | надёжность без VPN | `brain/brain.py` |

## Быстрый старт

```powershell
cd C:\jarvis
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

copy .env.example .env
notepad .env      # DEEPSEEK_API_KEY (Mistral — опционально)

python main.py --list-devices   # узнать индекс микрофона
python setup_tts.py --pull      # опционально: локальный голос Piper (~85 МБ)
python gui.py                   # визуальный интерфейс (или run_jarvis.cmd)
python main.py                  # консольный голосовой режим
```

Требования: Windows 10/11, Python 3.11+ (Tkinter входит в стандартный установщик),
~2 ГБ свободного места (модель Whisper), ключ DeepSeek (доступен без VPN;
Mistral — опционально, но у него может быть только платный план).

## Голос

Jarvis выбирает лучший доступный движок сам (`JARVIS_TTS_ENGINE=auto`):
**Piper** (локально, ~0.6 с, приватно) → **edge-tts** (голоса Microsoft, кэш
в `assets/tts_cache`) → **SAPI** (pyttsx3, офлайн-резерв).

Поставить локальный нейроголос (качает ~85 МБ, потом интернет не нужен):

```powershell
python setup_tts.py --pull            # мужской голос dmitri
python setup_tts.py --pull --voice irina   # женский
python setup_tts.py --check           # что установлено и какой движок выбран
python setup_tts.py --remove          # удалить Piper
```

Скрипт раскладывает Piper в `assets/piper/` и прописывает `JARVIS_PIPER_EXE` /
`JARVIS_PIPER_MODEL` в `.env`. Проверка голоса: `python -m dev.test_voice`.
Если облако недоступно и Piper не установлен — остаётся SAPI, ассистент
не замолкает.

## Обучение — свои команды (0 токенов, без LLM)

В GUI есть вкладка **«Обучение»**: пишешь фразу и действие, Jarvis выполняет
именно так и никогда не обращается к модели.

1. Фраза, которой будешь управлять: `включи музыку`
2. Что сделать: `Открыть сайт`
3. Значение: `https://music.yandex.ru`
4. «Сохранить» — готово: теперь «включи музыку», «Джарвис, включи музыку,
   пожалуйста» открывают твой сайт, а не общий «плей».

Кнопка **«Из последней команды»** подставит фразу и действие, которое ты только
что выполнил, — удобно закреплять удачные сценарии. **«Проверить фразу»**
показывает, что сработает: твоя команда / встроенное правило / уйдёт в LLM.

Действия: открыть сайт, запустить приложение, поиск в браузере, видео на
YouTube, музыка (play/pause/next/prev), громкость, записать заметку, ответить
фразой. Свои команды проверяются **раньше** встроенных правил, поэтому
переопределяют их.

Из консоли:

```powershell
python -m memory.lessons --add "включи музыку" open_url https://music.yandex.ru --alias "вруби музон"
python -m memory.lessons --list
python -m memory.lessons --test "включи музыку"
python -m memory.lessons --toggle <id>
python -m memory.lessons --remove <id>
```

Хранится в `config/lessons.json` (в git не попадает).

## Визуальный интерфейс

![Интерфейс Jarvis](assets/ui_preview.png)

Тёмный HUD в одном окне:

- **Круг-индикатор** показывает состояние: слушаю / жду команду / думаю / говорю / пауза.
- **Диалог** с временем, источниками ответа (локальный роутер или LLM) и текстом
  распознанной речи — видно, что именно услышал ассистент.
- **Микрофон**: выбор устройства прямо в окне, переключение без перезапуска.
- **Чувствительность**: пресеты 0.7x–3x — если речь тихая, поставь 1.5x или 2x,
  значение сохраняется в `.env`.
- **Кнопка-переключатель**: пауза/продолжить; если микрофон отвалился — «Включить микрофон».
- **Быстрые действия**: музыка, пауза, громкость, свернуть окна, время, YouTube, Discord.
- **Озвучка** и **безопасный режим** (dry-run) переключаются на лету.
- **Проверка связи** с LLM — статус провайдера в шапке.
- Опасные действия подтверждаются обычным диалогом «Да/Нет».
- Подсказки по клавишам: `Enter` — отправить, `Esc` — пауза, `Ctrl+M` — мини,
  `Ctrl+L` — очистить, `↑/↓` — история команд.

Запуск без консольного окна: `run_jarvis.cmd` (использует `pythonw.exe`).
Если микрофона нет или он занят — интерфейс автоматически переходит в текстовый режим.

### Мини-режим

Кнопка **«Мини»** в шапке или `Ctrl+M` — окно сжимается в компактную панель
480×104 поверх других окон (`JARVIS_COMPACT_TOPMOST=1`): индикатор состояния,
последний ответ, поле ввода, кнопки «вернуть» (`□`) и «свернуть» (`—`).
Обратно — та же кнопка или `Ctrl+M`. Удобно держать ассистента под рукой во
время работы или игры: панель не перекрывает экран и не забирает фокус, пока
в неё не кликнешь.

| Команда | Что делает |
|---|---|

| `python gui.py --no-audio` | GUI без микрофона (только текст) |
| `python main.py` | голосовой режим в консоли |
| `python main.py --text` | текстовый режим без микрофона (с контекстом реплик) |

`JARVIS_STT_COMPUTE`, `JARVIS_BRAIN_TIMEOUT` — полный список в `.env.example`.

## Работа без VPN

Прямые запросы к Groq/OpenRouter из РФ блокируются на уровне провайдера —
кодом это не обойти. Но **DeepSeek и Mistral доступны напрямую** (проверено:
`401 Unauthorized`, а не `403 Forbidden`), поэтому лучший вариант без VPN и без
нагрузки на компьютер — их облачные API.

### 1. DeepSeek или Mistral (облако, без VPN, без нагрузки на ПК)

1. Получи ключ:
   - **DeepSeek** (основной, уже настроен): https://platform.deepseek.com/api_keys
   - **Mistral** — опционально; бесплатный тариф доступен не всем, может
     потребоваться платный план: https://console.mistral.ai/
2. Добавь в `.env`:
```env
DEEPSEEK_API_KEY=...
# при наличии платного Mistral:
# MISTRAL_API_KEY=...
```
3. Проверь:
```powershell
python main.py --health
```

Ожидаемый ответ: `"via": "deepseek:deepseek-chat"`. Модель считается в облаке:
CPU/RAM ПК не занимаются, GPU не используется. Локально остаются только микрофон,
Whisper и интерфейс (Whisper — ~0.5 ГБ RAM, работает только во время прослушивания).

Цепочка: **DeepSeek → Mistral → YandexGPT → Groq → OpenRouter**. Mistral и
YandexGPT без ключей пропускаются; Groq/OpenRouter нужны только при VPN/прокси.

### 1.1 Через агрегатор AITUNNEL (200+ моделей, оплата в рублях)

Ключ и баланс — в панели aitunnel.ru, всё остальное — три строки в `.env`:

```env
DEEPSEEK_API_KEY=sk-aitunnel-...
DEEPSEEK_BASE_URL=https://api.aitunnel.ru/v1
DEEPSEEK_MODEL=mimo-v2.6-flash                # основная: дешевле всех (2.64 ₽/1000 команд)
DEEPSEEK_FALLBACK_MODEL=deepseek-v4.1-flash-1017   # резерв на том же ключе
JARVIS_PRICE_IN=0.56                          # цены для учёта расхода
JARVIS_PRICE_OUT=56
# «Думающие» модели по умолчанию тратят ~2 с на рассуждение до первого слова.
# Это отключается одним параметром (ответ и первый звук примерно вдвое быстрее):
JARVIS_BRAIN_EXTRA={"reasoning": {"effort": "none"}}
```

**Сколько это стоит.** Jarvis считает расход сам: в логе на каждую команду
пишется `Стоимость команды: 0.0029 ₽ (259 вход / 23 выход ток.)`, а в GUI
цена видна в строке источника ответа. Цены задаются в `.env`
(`JARVIS_PRICE_IN` / `JARVIS_PRICE_OUT`, ₽ за 1M токенов) и должны
соответствовать выбранной модели. Измеренная стоимость одной команды
(живые замеры на AITUNNEL, ~1400 входных токенов на агентную команду):

| Модель | Ввод/Вывод, ₽ за 1M | ₽ за 1000 команд | 9 задач-теста | 1-й токен |
|---|---|---|---|---|
| **`mimo-v2.6-flash`** (основная) | 0.56 / 56 | **2.64 ₽** | **9/9** | 0.6 с |
| `qwen3.7-flash` | 1.2 / 26 | 2.30 ₽ | 8/9 (теряет второе действие) | 1.5 с |
| `mistral-nemo` | 3.8 / 6 | 4.43 ₽ | 8/9 | 1.0 с |
| `deepseek-v4.1-flash-1017` (резерв) | 0.6 / 120 | 7.11 ₽ | 9/9 | 0.75–1.3 с |
| `deepseek-v4-flash` | 10 / 33 | ≈15 ₽ | 9/9 | 0.7 с |
| `deepseek-chat` | 51 / 178 | ≈80 ₽ | 9/9 | 1 с |

Локальные команды (громкость, музыка, приложения, время, YouTube, mute в
Discord) до модели не доходят и стоят 0 ₽ — при обычном дне это большинство
запросов.

Любое имя модели из каталога агрегатора можно поставить в `DEEPSEEK_MODEL`
(`deepseek-chat`, `deepseek-v3.2`, `gemini-2.5-flash`, `gpt-4o` и т.д.) —
меняется только строка в `.env`. Если параметр из `JARVIS_BRAIN_EXTRA`
провайдер не понимает, Jarvis получит 400, снимает этот параметр и повторяет
запрос сам (`--health` покажет все кандидаты цепочки, если что-то не так).

### 1.2 YandexGPT как резерв (тоже доступен из РФ без VPN)

```env
YANDEX_API_KEY=<Api-Key сервисного аккаунта>
YANDEX_FOLDER_ID=<id каталога>
YANDEX_MODEL=yandexgpt-lite     # или yandexgpt
```

Ключ создаётся в консоли Yandex Cloud (роль `ai.languageModels.user`), запросы
идут на OpenAI-совместимый эндпоинт `https://llm.api.cloud.yandex.net/v1`.
Если DeepSeek/Mistral ответили ошибкой — Jarvis сам продолжит на YandexGPT.

### 2. Прокси (если хочешь остаться на Groq/OpenRouter)

Подойдёт HTTP/SOCKS5-прокси: локальный порт VPN-клиента, отдельный прокси-сервис
или корпоративный прокси.

```env
JARVIS_PROXY=http://127.0.0.1:2080
# или JARVIS_PROXY=socks5://127.0.0.1:1080
```

Проверка:
```powershell
python main.py --health
```

В ответе будет `"proxy": "http://..."`. Если прокси не поднят — Jarvis быстро
сообщит `NETWORK`/`Connection error`, а не зависнет. Для socks5 установлен
`socksio` (уже в `requirements.txt`).

### 3. Свой релей (Cloudflare Worker или VPS)

Если прокси нет, можно поставить крошечный релей за пределами блокировки.
Готовый Worker: [tools/cloudflare_worker.js](tools/cloudflare_worker.js).

1. Создай Worker в Cloudflare, вставь код, задай секрет `RELAY_TOKEN`.
2. В `.env`:
```env
JARVIS_GROQ_BASE_URL=https://<worker>.workers.dev/groq
JARVIS_OPENROUTER_BASE_URL=https://<worker>.workers.dev/openrouter
JARVIS_RELAY_TOKEN=<тот же секрет>
```
3. `python main.py --health`.

Ключи API остаются у клиента; Worker только пересылает запросы. Вместо
Cloudflare можно поднять nginx на VPS с `proxy_pass` на `api.groq.com` и
`openrouter.ai`.

### 4. Локальная LLM на CPU (если готов отдать ресурсы ПК)

Самый независимый вариант: Ollama на этом же ПК, модель работает на CPU.

```powershell
# один раз скачать модель (нужен интернет)
python setup_local_llm.py --pull

# проверить
python main.py --health
```

Скрипт пропишет в `.env`:
```env
JARVIS_LOCAL_LLM=1
JARVIS_LOCAL_LLM_FIRST=1
JARVIS_LOCAL_LLM_MODEL=qwen2.5:7b
JARVIS_NO_GPU=1
```

Модель 7B занимает ~4–5 ГБ RAM и на CPU (12 потоков) отвечает примерно
5–15 токенов/с. Для слабого ПК можно взять модель меньше:
`python setup_local_llm.py --model qwen2.5:3b --pull`.

**Сейчас локальная модель отключена** (`JARVIS_LOCAL_LLM=0`, `JARVIS_LOCAL_ONLY=0`)
и выгружена (`ollama stop qwen2.5:7b`), чтобы не занимать RAM/CPU. Включить обратно:

```powershell
python setup_local_llm.py --local-only
```

- простой ответ/болталка: ~2–4 с (первый после простоя — до 10 с);
- команда с браузером/экраном: ~30–45 с (несколько шагов агента на CPU);
- локальные команды роутера (громкость, приложения, время) — мгновенно.

Проверка и управление:
```powershell
python main.py --health     # via: ollama:qwen2.5:7b
ollama ps                   # PROCESSOR: 100% CPU
ollama stop qwen2.5:7b      # освободить ~6 ГБ RAM
```

Плюс: интернет для мозга не нужен вообще. Минус: сложные многошаговые
браузерные сценарии на локальной модели медленнее и менее надёжны, чем на
Groq. Отключить локальную модель: `JARVIS_LOCAL_LLM=0` (или удалить строку).

Если нужно **полностью запретить облачные LLM** (например, чтобы не было
даже попыток соединения), добавь:
```env
JARVIS_LOCAL_ONLY=1
```
или запусти `python setup_local_llm.py --local-only --pull`. Тогда Jarvis
использует только Ollama, а браузер/Steam/Discord работают как обычно.

### Про GPU

По умолчанию `JARVIS_NO_GPU=1`:

- Whisper работает на CPU (`device=cpu`, `int8`);
- Ollama получает `num_gpu=0` — модель не загружается в видеопамять;
- Edge для браузера запускается с `--disable-gpu`;
- `CUDA_VISIBLE_DEVICES`/`HIP_VISIBLE_DEVICES` выставляются пустыми до импорта
  моделей, чтобы библиотеки не инициализировали GPU.

Если когда-нибудь захочешь GPU для Whisper — поставь `JARVIS_NO_GPU=0` и
`JARVIS_STT_DEVICE=cuda`.

## Если ассистент плохо слышит

1. В GUI выбери правильный микрофон в списке «Микрофон».
2. Подними «Чувствительность» до 1.5x–2x (значение сохранится в `.env`).
3. Проверь уровень в Windows: Параметры → Система → Звук → устройство ввода →
   громкость микрофона и «Усиление» (Microphone Boost).
4. Запусти диагностику — она покажет шум, порог и распознанный текст:

```powershell
python dev\mic_check.py --seconds 6
```

Детектор речи теперь работает по полосе 150–3800 Гц: гул, шипение и низкочастотный
фон отсекаются, а тихая речь ловится. Порог адаптируется к шуму комнаты, поэтому
больше не нужно кричать. Если микрофон очень тихий, помогает
`JARVIS_SENSITIVITY=2.0` в `.env` или одноимённый пресет в интерфейсе.

## Команды, работающие без сети

«Открой Steam», «запусти доту», «закрой Discord», «включи/выключи музыку»,
«громкость 30», «громче/тише», «выключи звук», «который час», «какое сегодня число»,
«открой ютуб», «найди диплом», «сверни все окна», «заблокируй компьютер»,
**«запиши заметку купить хлеб»**, **«что в заметках»**,
**«напомни через 15 минут позвонить маме»**, **«напомни в 18:30 созвон»**,
**«что в буфере обмена»**, **«сделай скриншот»** — и любые твои обучаемые команды.

Всё остальное уходит в LLM. Если LLM недоступен (нет VPN/кончилась квота),
локальные команды продолжают работать, а на остальные ассистент отвечает
«Мозг недоступен».

## Экран, браузер, Discord и Steam

Ассистент умеет не только открывать сайты, но и работать с ними по шагам:

- **«Что на экране?» / «Посмотри на экран и найди ошибку»** — делает скриншот,
  распознаёт текст через Windows OCR и отвечает по содержимому. Скриншоты
  сохраняются локально в `assets/` (в git не попадают).
- **«Включи видео …» / «Найди на ютубе …»** — ищет на YouTube и открывает
  первый результат в управляемом браузере.
- **«Открой сайт … и скажи, что там»** — открывает, читает страницу, форму,
  список кнопок; может нажать кнопку/ссылку и заполнить поле.
- **«Зарегистрируйся на …»** — открывает страницу регистрации, читает поля формы,
  заполняет имя/email из `JARVIS_USER_NAME`/`JARVIS_USER_EMAIL`. Пароль, капчу
  и финальное подтверждение оставляет пользователю.
- **Steam:** «открой стим магазин / библиотеку / друзей / загрузки».
- **Discord:** «замьють/размьють дискорд», «заглуши/верни звук»,
  «отправь в Discord в канал … сообщение …» (с подтверждением).

### Браузер: всё в твоём окне

По умолчанию (`JARVIS_BROWSER_MODE=main`) Jarvis **не открывает своё окно**:
ссылки и видео открываются вкладкой в уже запущенном браузере
(`webbrowser.open_new_tab`), а заголовок и текст страницы читаются по HTTP —
«открой сайт и скажи, что там» отвечает за секунду.

Без настройки работают: открыть сайт, поиск, включить видео, прочитать текст
страницы. Клики и заполнение форм требуют доступа к DOM — запусти браузер с
отладкой:

```powershell
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222
```

и Jarvis (`JARVIS_BROWSER_CDP=http://127.0.0.1:9222`) подключится к твоим
вкладкам по CDP — тоже без отдельного окна, с твоими логинами и историей.
Прежний отдельный профиль (`assets/browser_profile`) возвращается
`JARVIS_BROWSER_MODE=managed`.

**YouTube.** В некоторых сетях `youtube.com` не резолвится вообще (Edge тогда
показывает `ERR_NAME_NOT_RESOLVED`). Jarvis проверяет это за миллисекунды и
вместо ошибки открывает тот же запрос в доступном сервисе — по умолчанию
Яндекс.Видео (`JARVIS_VIDEO_FALLBACK=yandex|vk|google|none`).

### Музыка: «включи музыку кишлак»

Фраза разбирается на исполнителя и трек — Jarvis понимает, **что** включать:

| Скажешь | Поймёт как |
|---|---|
| «включи музыку кишлак» | исполнитель/трек: `кишлак` |
| «поставь песню мирный воин» | `мирный воин` |
| «включи что-нибудь из Кишлака» | `кишлака` |
| «вруби трек кислород» | `кислород` |
| «включи музыку» | просто музыка (или твоя обученная команда) |
| «выключи музыку», «пауза», «стоп» | пауза/стоп (не поиск!) |

Порядок воспроизведения:

1. **Локальные файлы** — `JARVIS_MUSIC_DIR` (по умолчанию `%USERPROFILE%\Music`).
   Находит по «исполнитель — название», играет сам через sounddevice: мгновенно,
   без интернета, с паузой/продолжить/стоп. Ничего не открывает.
2. **Онлайн-превью** (`JARVIS_MUSIC_ONLINE=1`, по умолчанию) — если файла нет,
   Jarvis ищет трек в открытом каталоге (iTunes, запасной Deezer), скачивает
   30-секундный фрагмент и **играет его сам**: ~1–2 с от фразы до звука, без
   логина, без браузера и без окон. Исполнитель определяется раньше названия,
   поэтому «кишлак» — это Кишлак, а «миража» находит Mirazh. Превью кэшируются в
   `assets/music_cache`.
3. **Фоновое окно за экраном** (`python setup_music.py`): один раз входишь в
   VK / Яндекс.Музыку в профиле Jarvis — дальше он сам открывает поиск, жмёт
   «играть» и проверяет, что звук пошёл (полный трек, а не 30 с). Окно за
   пределами экрана (`JARVIS_MUSIC_AUTOPLAY=1`).
4. **Вкладка в основном браузере** — «включи … целиком» или если превью
   выключено: открывается точный поиск трека (`JARVIS_MUSIC_WEB=yandex|vk|zvuk`),
   остаётся один клик. Jarvis так и говорит, без «включил».

Превью — 30 секунд, потому что полные треки в стриминге защищены DRM и требуют
входа в аккаунт: полный звук дают локальные файлы (пункт 1) или авто-плей в
пункте 3.

Проверка: `python setup_music.py --check` → сервис, профиль, сколько локальных
треков видит.

Сложные команды выполняет агентный цикл: LLM вызывает инструмент, получает
результат и решает, что делать дальше (до 8 шагов). Для простых команд
по-прежнему работает локальный роутер за миллисекунды.

Playwright использует уже установленный Edge — отдельный Chromium качать не нужно.

**Чего ассистент не делает без тебя:** не вводит пароли, не проходит капчу/SMS,
не оплачивает покупки. Регистрация, отправка сообщений, покупка и клики по
экранным кнопкам подтверждаются в GUI/голосом.

```

 ├─ ui/app.py           Tkinter-окно: диалог, орб, быстрые действия, настройки
 └─ ui/controller.py    фоновый движок: слух -> роутер/мозг -> действия -> озвучка
main.py           консольный режим и CLI-команды
setup_tts.py      установка локального голоса Piper
 ├─ ears/listener.py      один открытый аудиопоток, VAD-эндпоинтинг, калибровка шума
 ├─ ears/wake.py          поиск wake word с защитой от ложных срабатываний
 ├─ ears/model_manager.py faster-whisper: лёгкая wake-модель + основная с выгрузкой
 ├─ brain/skills.py       скилы: инструменты + короткая инструкция под задачу
 ├─ memory/lessons.py     обучаемые команды пользователя (0 токенов)
 ├─ hands/reminders.py    напоминания и таймеры (спят до срока)
 ├─ hands/music.py        разбор «включи …», локальный плеер, фоновое воспроизведение
 ├─ common/guard.py       защита от prompt injection (внешний текст = данные)
 ├─ common/priority.py    пониженный приоритет процесса (не мешать играм)
 ├─ memory/sanity.py      фильтр галлюцинаций STT (без тяжёлой морфологии)
 ├─ memory/router.py      локальные интенты (0 токенов)
 ├─ memory/apps.py        алиасы приложений + Steam-игры
 ├─ memory/intent_cache.py точный кэш успешных интентов (SQLite, TTL)
 ├─ brain/brain.py        цепочка LLM, выбор инструментов, стриминг, агентный цикл
 ├─ hands/hands.py        приложения, звук, файлы, питание, экран, Discord/Steam
```

GUI и консоль используют один и тот же движок: `ui/controller.py` для окна и
`main.py` для терминала, поэтому поведение команд идентично.

Конфигурация: `config.py` (пути, пороги, цепочка моделей), `config/*.json`
(приложения, Steam-игры, детектор game-режима), `.env` (ключи и переопределения).

## Что оптимизировано

### Скилы и промпты (минимум токенов, максимум точности)

Промпт собран из трёх частей: **короткое ядро** (7 правил, ~330 токенов),
**инструкция активных скилов** (1–3 строки) и **схемы только нужных
инструментов**. Скил — это «браузер», «экран», «Discord», «Steam»,
«клавиатура/мышь», «файлы и поиск», «музыка и звук», «питание», «заметки и
напоминания», «YouTube» (`brain/skills.py`).

Замеры на живом API (одна и та же фраза, промпт + схемы инструментов):

| Фраза | Было | Стало | Инструментов |
|---|---|---|---|
| «запусти доту» | 1188 ток. | **568 ток.** (−52%) | 3 из 25 |
| «открой сайт dns-shop и узнай цену» | 1605 ток. | **1027 ток.** (−36%) | 8 из 25 |
| «что на экране» | ~1400 ток. | **785 ток.** | 5 из 25 |
| вопрос без действия (чат) | 249 ток. | **266 ток.** | без схем |

Качество при этом не упало: в тесте из 9 типичных команд (включая
мульти-действия, напоминание и заметку) — **9/9 верных вызовов**.

### P0 — экономия токенов, безопасность, скорость ответа

- **Динамический набор инструментов.** В запрос уходят только релевантные схемы
  (3–8 вместо 25): −30…50% токенов промпта и меньше шансов, что модель вызовет
  «не ту» функцию. Выбор по ключевым словам фразы + семья инструментов
  (браузер/Discord/Steam) + инструменты прошлой реплики. Если модель всё же
  «поговорила» вместо действия — один повтор с полным набором
  (`JARVIS_TOOLS_RETRY`). Настройка: `JARVIS_TOOLS_MAX`.
- **Защита от prompt injection.** Текст страниц, OCR и результаты браузера идут
  в модель только внутри блока `<external_data>`: `common/guard.py` вырезает
  «игнорируй инструкции», `system:`, `<|im_start|>`, bidi-символы и прочие
  команды модели, а системный промпт требует выполнять указания только
  пользователя. Опасные действия всё равно подтверждаются.
- **Стриминг LLM → TTS.** Ответ режется на фразы по мере генерации: пока
  звучит первая фраза, синтезируется вторая (два потока в `StreamSpeaker`).
  Первый звук — ~1 с вместо 3–5 с. Болталка без действий идёт отдельным
  потоковым запросом вообще без схем функций (`JARVIS_CHAT_FASTPATH`).

### P1 — контекст, зрение, слух

- **Контекст 2–3 реплик.** Уточнения («а на ютубе?», «и там же», «сделай ещё
  раз») понимаются без повторов; «повтори» вообще не тратит токены —
  выполняется прошлый интент локально. Настройка: `JARVIS_CONTEXT_TURNS`.
- **OCR активного окна + кэш.** Распознаётся только текущее окно (меньше
  пикселей и приватнее: в LLM не попадает содержимое остальных окон), координаты
  пересчитываются в экранные для кликов, а повторный вопрос по тому же окну
  берётся из кэша (`JARVIS_OCR_CACHE_SEC`, по умолчанию 20 с — в 20+ раз быстрее).
- **Лёгкий wake word.** В простое слушает модель `tiny` (~75 МБ): «Джарвис» ловится
  дёшево по CPU и памяти, тяжёлая `small` включается только когда wake word
  прозвучал, и выгружается после `JARVIS_STT_IDLE_UNLOAD` секунд простоя
  (по умолчанию 900, освобождает ~0.5 ГБ RAM). Речь команды всё равно
  распознаётся точной моделью.

### P2 — голос и надёжность

- **Piper / edge-tts.** Локальный нейроголос Piper (~0.6 с, офлайн) или голоса
  Microsoft через edge-tts с кэшем; SAPI — всегда доступный резерв. Движок
  выбирается автоматически, при сбое сети/движка переключение происходит
  на лету (см. раздел «Голос»).
- **YandexGPT как fallback.** Второй провайдер, доступный из РФ без VPN:
  встаёт в цепочку сразу после Mistral, поэтому при ошибке DeepSeek ассистент
  отвечает, а не молчит.

### Что было раньше

- **Один аудиопоток** вместо открытия `InputStream` на каждую реплику (−0.1…0.2 с
  на команду, меньше сбоев USB-микрофона).
- **Ленивые импорты**: `openai`, `faster_whisper`, `edge_tts`, `pyttsx3` не грузятся,
  пока не нужны. `import main` ускорен примерно в 10 раз.
- **Кэш интентов только по точной фразе** — быстрее и без риска выполнить
  противоположную команду (`включи`/`выключи`).
- **Карантин LLM-моделей**: 404/403/429 не повторяются на каждой команде.
- **Индекс ярлыков** кэшируется и сам пересобирается раз в неделю.
- **Громкость** через pycaw без лишних нажатий клавиш; медиа — через `keybd_event`.
- **Детектор речи** работает по полосе 150–3800 Гц с адаптацией к шуму: гул и
  шипение отсекаются, тихая речь ловится без крика.

## Звук: почему не шумит

Речь и музыка идут через один модуль [common/audio.py](C:\jarvis\common\audio.py):

- **одно устройство вывода** (`JARVIS_AUDIO_OUTPUT`, по умолчанию системное) —
  раньше TTS и плеер могли открывать разные потоки на разных устройствах
  (колонки 8 каналов / HDMI 48 кГц / Bluetooth-гарнитура 8 кГц), и драйвер
  выдавал хрип;
- **частота устройства** — сигнал ресемплируется в неё один раз, а не «как
  получится»;
- **лимитер** на 0.9 (`JARVIS_AUDIO_PEAK`): громкие треки не клиппуют в треск;
- **музыка ставится на паузу, пока Jarvis говорит** (`JARVIS_AUDIO_DUCK`,
  по умолчанию 0.25; поставь `1`, если хочешь, чтобы музыка не прерывалась), —
  поэтому речь и музыка не смешиваются в «шум»;
- параметры каждого воспроизведения пишутся в лог: устройство, частота,
  каналы, пик.

Диагностика: `python -m common.audio` (список устройств + тихий тон 1.5 с) и
`python main.py --list-devices` (входы и выходы, «*» — текущий выход).
Если слышно не то устройство — пропиши нужное в `.env`:
`JARVIS_AUDIO_OUTPUT=Headphones`.

## Не мешает компьютеру

- Процесс запускается с приоритетом **BELOW_NORMAL** (`JARVIS_LOW_PRIORITY=1`):
  игры и тяжёлые программы получают CPU первыми, Jarvis забирает только простой.
- **EcoQoS** (`JARVIS_ECO_MODE=1`, Windows 11) — приоритет на энергоэффективные
  ядра; по умолчанию выключен, чтобы не добавить задержку на слабых CPU.
- Штатный режим не держит нагрузку в простое: wake word проверяет лёгкая модель
  (`tiny`), тяжёлая выгружается после `JARVIS_STT_IDLE`, напоминания спят на
  условии (без опроса), GPU не используется вообще.
- В игре индикатор микрофона обновляется реже (0.3 с вместо 0.06 с), а в
  свёрнутом/нефокусированном окне анимация рисуется по
  `JARVIS_UI_FPS_BACKGROUND` (4 кадра/с).
- Один аудиопоток, Whisper в int8 и с ограничением потоков, без фоновых
  браузерных сессий (Playwright закрывается вместе с Jarvis).

## Безопасность

- Опасные действия (выключение, перезагрузка, сон) требуют подтверждения:
  в GUI — модальное окно «Да/Нет», в консоли — голос или ввод «да».
- `launch_app` не использует `shell=True`; имена проверяются на метасимволы.
- `--dry-run` / `JARVIS_DRY_RUN=1` позволяют прогнать пайплайн без действий.
- Регистрация, отправка сообщений в Discord, клики по экранным кнопкам и
  «опасные» кнопки в браузере (регистрация/оплата/удаление) подтверждаются.
- Пароли, капча, SMS и платежи не автоматизируются — это остаётся пользователю.
- Браузер использует отдельный профиль `assets/browser_profile`; логины хранятся
  локально и не попадают в git.
- Скриншоты лежат в `assets/` локально; в LLM уходит только OCR-текст и только
  когда ты просишь «посмотреть экран». Сейчас OCR снимает **только активное
  окно**, а не весь экран. `.env`, записи, профиль и кэш озвучки — в `.gitignore`.
- **Внешний текст не становится инструкцией.** Всё, что пришло из интернета или
  с экрана, попадает в модель в блоке `<external_data>` после очистки от
  попыток инъекции (`common/guard.py`, выключить: `JARVIS_GUARD=0`). Даже если
  страница напишет «выключи компьютер», ассистент сообщит об этом и спросит
  подтверждение, а не выполнит.

## Известные ограничения

- Wake word определяется через Whisper по фразе, а не отдельным детектором
  (сейчас — лёгкой моделью `tiny`): реакция ~0.3–0.8 с, возможны ложные
  срабатывания на похожих словах.
- Нет barge-in: пока ассистент говорит, микрофон заглушён.
- Клики и заполнение форм в **основном** браузере требуют запуска с
  `--remote-debugging-port=9222` (CDP). Без него Jarvis открывает и читает
  страницы, но не нажимает кнопки.
- `youtube.com` может не резолвиться на уровне сети — тогда «включи видео»
  открывает поиск в доступном сервисе (`JARVIS_VIDEO_FALLBACK`), а не видео
  на YouTube.
- Стриминговая озвучка звучит по фразам: если провайдер оборвётся посреди
  ответа, прозвучавшая часть не повторяется, остальное сообщается как ошибка.
- edge-tts иногда отдаёт пустое аудио на короткие фразы: делается повтор, при
  неудаче — автоматический переход на Piper/SAPI (без пауз в речи).
- Бесплатные LLM-модели периодически меняются; актуальные проверяй
  `dev\probe_models.py` и правь `config.BRAIN_CHAIN`.
- GUI требует Tkinter (есть в стандартном Python для Windows). На экранах уже
  1366×768 окно автоматически уменьшается, но интерфейс рассчитан на десктоп.
- Discord mute/deafen — горячие клавиши-переключатели (состояние Discord
  локально не читается), поэтому команда «замьють» переключает микрофон,
  а не гарантирует именно выключение.
